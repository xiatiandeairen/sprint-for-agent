# collect

## Purpose

收集和整理能支撑分析的材料，形成证据清单。

只回答一件事：**有哪些证据可以用，它们可靠到什么程度**。

不做：
- 不急着下结论
- 不把所有材料全文搬进 handoff
- 不收集和 scope 无关的信息

## Steps

### 0. 用户提示和门禁

进入本 stage 时告诉用户：将收集哪些材料、为什么需要、不会看哪些范围。

必须停下来等用户的情况：
- 需要读取仓库文件、日志、git 历史、外部资料或用户未明确授权的材料来源
- 多个材料来源可选，且来源优先级会影响结论
- 材料缺口会明显降低结论置信度，用户需要选择“补证 / 继续有限分析 / 调整问题”
- 发现 scope 外材料，想纳入分析

### 1. 制定取证计划

根据 scope 判断材料来源：
- 用户提供的文本、文件、截图、日志、数据
- 仓库内文档或代码（只为理解分析对象，不做代码改动）
- git 历史（只在反复问题或演化判断相关时）
- web search（只在外部事实、当前信息、官方规范会影响判断时）

### 2. 收集材料

规则：
- 优先原始材料，其次二手摘要
- 记录来源和时间敏感性
- 对不可靠、过期、样本偏差材料降权
- 需要 web 时，遵守系统 browsing 要求并优先官方 / primary sources

### 3. 形成证据清单

handoff 模板：

```markdown
证据清单:
| id | 来源 | 关键内容 | 可靠性 | 用途 |
|---|---|---|---|---|
| E1 | {来源} | {摘要} | high/medium/low | {支撑哪个问题} |

缺口:
- {缺失证据及影响；没有写 None}

取证限制:
- {样本、时效、权限、口径限制；没有写 None}
```
