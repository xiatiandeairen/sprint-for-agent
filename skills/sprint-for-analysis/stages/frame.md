# frame

## Purpose

选择分析框架，把问题拆成可判断的维度、假设或比较口径。

只回答一件事：**准备用什么结构分析，为什么这个结构适合当前问题**。

不做：
- 不新增范围
- 不开始写最终结论
- 不为了形式套复杂模型

## Steps

### 0. 用户提示和门禁

进入本 stage 时告诉用户：准备用什么框架分析，以及这个框架会怎样影响后续判断。

必须停下来等用户的情况：
- 存在多个合理分析框架，且会导向不同结论形态
- 判断维度或权重会影响取舍
- 需要新增自定义框架，而不是使用内置框架
- 框架选择会改变 scope 中的分析边界或成功标准

### 1. 选择框架

按任务类型选择最小框架：
- 根因分析：现象 → 直接原因 → 系统原因 → 触发条件 → 证据
- 方案比较：目标 → 约束 → 选项 → 维度 → trade-off
- 技术 / 产品调研：问题 → 外部约束 → 可选路径 → 风险 → 适用条件
- 数据 / 日志解读：口径 → 样本 → 模式 → 异常 → 替代解释
- 需求分析：用户目标 → 必须有 → 可后做 → 风险 → 验收信号
- 文档审阅：主张 → 证据 → 缺口 → 歧义 → 修改建议

### 2. 定义判断维度

每个维度必须：
- 直接服务核心问题
- 有证据来源或可人工判断
- 不超过 7 个，优先 3-5 个

### 3. 输出分析框架

handoff 模板：

```markdown
分析框架:
- 类型: {root-cause / comparison / research / data-interpretation / requirements / document-review / custom}
- 选择原因: {为什么适合}

判断维度:
| 维度 | 要回答的问题 | 证据来源 | 权重 |
|---|---|---|---|
| {维度} | {问题} | {E id / 待补} | high/medium/low |

不采用的框架:
- {框架 + 原因；没有写 None}
```
