# synthesize

## Purpose

把分析发现收敛成决策可用的结论、建议、限制和用户交付摘要。

只回答一件事：**用户现在应该怎么理解这件事，以及下一步怎么做**。

不做：
- 不新增证据
- 不隐藏不确定性
- 不把建议写成已授权执行
- 不重复完整 handoff

## Steps

### 0. 用户提示和门禁

进入本 stage 时告诉用户：这是最终综合，不新增证据，只把已确认发现转成结论、限制和下一步建议。

必须停下来等用户的情况；触发时输出后暂停，等待用户回复：
- 是否给明确推荐会影响交付形态，用户尚未确认
- 推荐偏向依赖价值取舍，如成本优先、风险优先、速度优先、体验优先
- 只能低置信度交付，用户需要确认是否接受有限结论
- 下一步建议会变成执行动作；只能列建议，不能自动执行

### 1. 生成核心结论

结论必须：
- 直接回答 scope 的核心问题
- 标注 confidence
- 给出最关键依据
- 说明适用条件和限制

### 2. 生成建议或选项

按任务类型输出：
- 需要决策：推荐选项 + 不选其他选项的理由
- 根因分析：最可能根因 + 触发条件 + 建议验证
- 调研：可行路径 + 适用条件 + 风险
- 数据 / 日志：模式解释 + 下一步取证
- 文档审阅：主要问题 + 修改方向

### 3. 输出综合结果

按使用场景选择交付形态：
- 决策：结论 → 推荐 → trade-off → 风险 → 下一步
- 排查：现象 → 最可能原因 → 证据 → 还缺什么 → 下一步取证
- 汇报：背景 → 发现 → 影响 → 建议 → 限制
- 学习：解释 → 关键概念 → 判断方法 → 注意事项

用户可见输出必须包含：
- 一句话结论
- confidence
- 关键依据
- 建议下一步
- 主要限制

handoff 模板：

```markdown
核心结论:
- {结论} (confidence: high/medium/low)

关键依据:
- {E id / 发现}: {一句话}

建议:
- {建议 / 选项 / 下一步；没有写 None}

限制:
- {证据不足、口径限制、时效限制；没有写 None}

后续机会:
- {scope 外但有价值的问题；没有写 None}

交付摘要:
- 一句话结论: {结论}
- confidence: {high/medium/low}
- 用户应关注: {1-3 点}
- 建议下一步: {1-3 点；没有写 None}
- 主要限制: {1-3 点；没有写 None}
```
