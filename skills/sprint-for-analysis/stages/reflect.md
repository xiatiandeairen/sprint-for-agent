# reflect

## Purpose

复盘分析过程，沉淀可复用方法和后续机会。

只回答一件事：**这次分析有什么方法经验或下次应改进的地方**。

不做：
- 不重写结论
- 不新增范围
- 不为了占位写空洞总结

## Steps

### 1. 判断是否需要复盘

需要 reflect 的情况：
- 分析过程出现证据不足、口径反复或范围调整
- 使用了可复用框架
- 发现后续值得产品化 / 模板化的分析能力
- 用户明确要求沉淀

不需要时直接写 `无`。

### 2. 输出复盘

handoff 模板：

```markdown
复盘:
- 有效方法: {这次有效的分析方式；没有写 None}
- 主要偏差: {范围 / 证据 / 口径问题；没有写 None}
- 下次改进: {可执行改进；没有写 None}
- 可沉淀模板: {模板 / 检查表 / 数据口径；没有写 None}
```
