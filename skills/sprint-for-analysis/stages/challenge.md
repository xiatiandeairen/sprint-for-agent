# challenge

## Purpose

对关键发现做反证和置信度校准。

只回答一件事：**这些结论哪里可能错，错了会因为什么**。

不做：
- 不重新收集所有材料
- 不推翻一切只为显得谨慎
- 不引入 scope 外的新目标

## Steps

### 0. 用户提示和门禁

进入本 stage 时告诉用户：将尝试反证关键判断、检查替代解释并校准置信度。

必须停下来等用户的情况：
- 关键结论被降级或删除，且影响最终建议
- 出现新的替代解释，需要决定是否纳入本期
- 判断“是否足以进入综合”为 no，用户需要选择“补证再跑一轮 / 带限制进入 synthesize / 终止本次分析”
- loop 达到 max 后仍证据不足，用户需要确认最终状态

### 1. 选择需要挑战的结论

必须挑战：
- 会影响最终建议的结论
- confidence 不是 high 但被用于决策的结论
- 证据来源单一的结论
- 存在明显替代解释的结论

### 2. 做反证检查

检查：
- 是否有相反证据
- 是否有替代解释
- 是否存在样本偏差 / 口径偏差 / 时效问题
- 是否把相关性误当因果
- 是否有未验证前提

### 3. 校准结论

handoff 模板：

```markdown
反证检查:
| 结论 | 可能错误原因 | 反证 / 替代解释 | 处理 |
|---|---|---|---|
| {结论} | {原因} | {说明} | 保留 / 降级 / 删除 / 需补证 |

置信度调整:
- {结论}: {high/medium/low} → {high/medium/low}，原因 {一句话}

是否足以进入综合:
- {yes/no}
- 原因: {一句话}
- 若 no，下一轮需要补: {证据 / 口径 / 对象}
```
