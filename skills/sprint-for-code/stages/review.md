# review

## Purpose

把当前代码变更整理成便于用户验收的说明。

只回答一件事：**用户应该重点看什么、怎么验收、哪些变化需要理解**。

不做：
- 不改代码
- 不跑机械验证
- 不重新设计
- 不重新拆任务
- 不做完整代码评审
- 不替用户完成主观验收

## Steps

### 1. 读取可用验收上下文

目标：确认有足够信息生成验收说明。

步骤：

1. 读取可用上下文。可用上下文可能包括：
  - 用户原始目标
  - 已确认成功标准
  - 当前 git diff / commit
  - 已有执行结果
  - 已有验证结果
  - 人工验收项
  - 风险 / 阻塞记录
2. 如果缺少完整执行结果，但有当前 diff 和用户描述，则基于可观察变更生成最小验收说明。
3. 如果没有目标、变更或可验收对象，停止并输出阻塞项：缺少什么、为什么无法 review。

展示模板：

```markdown
我会基于这些内容整理验收说明：

- 目标：{目标}
- 变更：{变更摘要}
- 验证：{已有验证结果；没有写“未提供”}
- 需要人工看的点：{人工验收项；没有写“无”}
```

### 2. 提炼重要变更

目标：把代码改动翻译成用户能理解的变化，不复述文件 diff。

步骤：

1. 从当前变更中提炼 1-6 条重要变更。
2. 每条说明：
  - 改了什么
  - 为什么重要
  - 用户可能在哪里感知到
3. 不列无关重排、格式化、机械改名，除非会影响验收。

展示模板：

```markdown
重要变更：

| 变更 | 为什么重要 | 用户在哪里看 |
|---|---|---|
| {变更} | {原因} | {页面 / API / 行为 / 文件 / 无用户可见变化} |
```

### 3. 评估影响面

目标：告诉用户这次变更可能影响哪些范围，方便决定验收深度。

影响维度：

| 维度 | 例子 |
|---|---|
| 用户可见行为 | 页面、交互、文案、错误提示 |
| 接口 / 数据 | API、字段、状态、配置 |
| 兼容性 | 调用方、新旧逻辑、迁移 |
| 权限 / 安全 | 登录、权限、隐私、支付 |
| 性能 / 稳定性 | 慢路径、重试、缓存、并发 |
| 运维 / 发布 | 环境变量、脚本、部署、回滚 |
| 测试 / 验证 | 新增测试、需要人工验收的场景 |

步骤：

1. 按影响维度逐项判断是否涉及。
2. 只展示涉及或需要用户注意的维度。
3. 如果影响不确定，明确写“需人工确认”。

展示模板：

```markdown
影响面：

| 影响点 | 范围 | 说明 |
|---|---|---|
| {影响点} | {局部 / 跨模块 / 用户可见 / 外部系统} | {说明} |
```

### 4. 生成验收场景

目标：把成功标准和影响面转成用户可以执行的验收场景。

步骤：

1. 生成验收场景：
  - 主路径：最核心成功路径
  - 回归路径：容易被本次改动影响的旧行为
  - 边界路径：错误、空数据、权限、异常情况
  - 人工路径：自动验证无法覆盖的主观或外部环境检查
2. 每个场景说明：
  - 怎么操作 / 观察
  - 期望结果
  - 是否必须验收
3. 没有对应场景的类型不展示。

展示模板：

```markdown
建议验收场景：

| 场景 | 怎么验 | 期望结果 | 必须 |
|---|---|---|---|
| {场景} | {操作 / 检查方式} | {期望结果} | 是 / 否 |
```

### 5. 标记注意事项

目标：把验收时容易漏掉的风险和限制集中提示给用户。

步骤：

1. 汇总需要用户知道的注意事项：
  - 未自动验证的内容
  - 需要真实环境确认的内容
  - 行为变化或兼容限制
  - 已知风险 / 非阻塞问题
  - 不属于本次范围的内容
2. 不制造风险；没有事实依据写 None。

展示模板：

```markdown
验收注意事项：

- {注意事项；没有写“无”}
```

### 6. 锁定验收说明

目标：给用户展示最终验收说明，并写入 handoff。

步骤：

1. 确认以下条件：
  - 重要变更已经解释清楚
  - 影响面已覆盖用户需要知道的范围
  - 验收场景能支撑用户判断是否接受代码
  - 人工验收和未验证项没有被写成已通过
2. 给用户展示验收说明。
3. 按本步骤的 handoff 模板生成 `append_stage` operation 的 `{BODY}`。

展示模板：

```markdown
验收说明已整理 ✓

重点变更：
- {变更摘要}

建议验收：
- {场景}

需要注意：
- {风险 / 人工验收 / 未覆盖项；没有写“无”}
```

handoff 模板：

```markdown
验收说明:
{一句话说明这次该怎么验收}

重要变更:
- {重要变更；没有写 None}

影响面:
- {影响点；没有写 None}

验收场景:
- {场景}: {期望结果}

注意事项:
- {人工验收 / 未验证 / 风险 / 范围外；没有写 None}
```

规则：

- 不记录完整 diff。
- 不复述完整执行过程。
- 不隐藏用户需要手动看的点。
- 不把机械验证结果等同于用户验收通过。
- 只有完成本步骤展示和 handoff 写入，review 才算完成。
