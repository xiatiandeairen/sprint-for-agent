# reflect

## Purpose

从当前 sprint 的实际执行结果中提炼可复用改进。

只回答一件事：**下一次同类任务怎样更快、更稳、更少返工**。

不做：
- 不重新定义需求
- 不重新设计
- 不重新拆任务
- 不做代码评审
- 不复述完整执行过程
- 不把一次偶发问题强行上升为规则

## Steps

### 1. 读取可用复盘上下文

目标：确认有足够事实可以复盘。

步骤：

1. 读取可用上下文。可用上下文可能包括：
  - 用户原始目标
  - 已有 stage 结果
  - 当前 git diff / commit
  - 验证结果
  - 阻塞 / 风险
  - 用户调整过的流程
  - 人工验收点
  - 失败和返工记录
2. 如果缺少完整执行结果，但有当前变更和用户描述，则做最小复盘。
3. 如果没有任何可复盘事实，停止并输出阻塞项：缺少什么、为什么无法复盘。

展示模板：

```markdown
我会基于这些事实做复盘：

- 目标：{目标}
- 结果：{完成 / 部分完成 / 阻塞}
- 验证：{验证结果}
- 调整 / 偏离：{有则列出；没有写“无”}
```

### 2. 提取事实

目标：只提取对复盘有用的事实，不写主观感想。

步骤：

1. 提取事实：
  - 完成了什么
  - 哪些验证通过 / 失败 / 未跑
  - 哪里发生阻塞
  - 哪里发生范围调整、人工确认或偏离
  - 哪些判断后来被证明有效 / 无效
2. 每条事实必须能从可用上下文找到依据。
3. 无依据的内容不写。

展示模板：

```markdown
可复盘事实：

| 事实 | 依据 |
|---|---|
| {事实} | {来源：结果 / 验证 / diff / 用户调整} |
```

### 3. 识别模式

目标：判断这次经验属于哪个层次，避免只记录表面现象。

模式层次：

| 层次 | 说明 |
|---|---|
| 需求对齐 | 目标、范围、成功标准是否清楚 |
| 设计覆盖 | 接口、数据、流程、错误、兼容是否提前定清 |
| 计划拆分 | 文件清单、任务边界、验证锚点是否合理 |
| 执行粒度 | task 是否需要拆 unit，模型执行是否稳定 |
| 验证锚点 | 验证是否覆盖真实风险 |
| 人工检查点 | 是否该让用户中途确认 |
| 工具 / 环境 | 测试、构建、依赖、权限、worktree 等环境问题 |

步骤：

1. 把事实归入 0-3 个最重要的模式层次。
2. 每个模式必须有事实依据。
3. 没有明显模式时写“未发现可泛化模式”。

展示模板：

```markdown
我看到这些模式：

| 模式 | 依据 | 影响 |
|---|---|---|
| {层次 / 模式} | {事实依据} | {对后续任务的影响} |
```

### 4. 产出改进建议

目标：把复盘转成可执行改进，而不是泛泛总结。

建议类型：

| 类型 | 用途 |
|---|---|
| 下次同类任务建议 | 下次遇到类似任务时怎么做 |
| 流程 / 规则建议 | 是否应该调整 stage 或规则 |
| 沉淀候选 | 是否值得沉淀为模板、检查项、文档或自动化 |

步骤：

1. 基于 §3 的模式产出建议。
2. 每条建议必须能追溯到事实。
3. 不自动修改规则文件；只提出建议。
4. 如果只是偶发问题，不写成规则建议。

展示模板：

```markdown
改进建议：

| 建议 | 类型 | 依据 |
|---|---|---|
| {建议} | 下次同类任务 / 流程规则 / 沉淀候选 | {事实或模式} |
```

### 5. 锁定复盘结果

目标：给用户展示复盘结论，并写入 handoff。

步骤：

1. 确认以下条件：
  - 复盘事实都有依据
  - 模式没有超过 3 个
  - 建议能追溯到事实
  - 没有把偶发问题强行写成规则
2. 给用户展示复盘结果。
3. 按本步骤的 handoff 模板生成 `append_stage` operation 的 `{BODY}`。

展示模板：

```markdown
复盘结果已记录 ✓

结论：
{一句话}

改进建议：
- {建议；没有写“无”}

沉淀候选：
- {候选；没有写“无”}
```

handoff 模板：

```markdown
复盘结论:
{一句话；没有可复盘内容时写 None}

事实:
- {事实；没有写 None}

模式:
- {模式；没有写 None}

改进建议:
- {建议；没有写 None}

沉淀候选:
- {模板 / 检查项 / 文档 / 自动化候选；没有写 None}
```

规则：

- 不记录完整过程。
- 不写无依据的主观评价。
- 不写鸡汤。
- 不把一次偶发问题强行上升为规则。
- 只记录对未来有用的信息。
- 只有完成本步骤展示和 handoff 写入，reflect 才算完成。
