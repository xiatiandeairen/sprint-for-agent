# sprint-for-agent Roadmap

## 1. 产品愿景

AI agent 的结构化任务执行引擎。让 agent 在执行复杂任务时保持方向正确、过程可见、质量可控。

| | |
|---|---|
| **目标用户** | 使用 AI agent 完成软件工程任务的开发者 |
| **核心差异** | 不是辅助工具，而是执行约束 — 通过流水线和验证机制限制 agent 的自由度来提升可靠性 |

## 2. 核心价值

AI agent 的能力在快速提升，但**可靠性**没有同步跟上。模型越强，自由发挥时偏离目标的破坏力越大。当前的解决方式要么是人工盯着（不可规模化），要么是事后修复（成本高）。

sprint 的赌注是：**在执行过程中施加结构化约束，比事后修复更便宜，比人工监督更可规模化。** 如果这成立，任何用 agent 做复杂任务的场景都需要类似的执行引擎。

## 3. 版本规划

### v1 — 单项目可用 ✅

| 维度 | 标准 | 状态 |
|------|------|------|
| **功能** | 用户可以用 sprint 驱动任意项目的任务执行，不需要修改 sprint 源码 | ✅ M2 + M4 |
| **质量** | 核心流程有自动化测试覆盖，anchor 验证可用于非 Swift 项目 | ✅ M3 (42 tests) |
| **用户** | 作者本人在 ≥2 个不同项目中持续使用 | ✅ 多项目使用中 |

#### 里程碑

| # | 里程碑 | 验证点 | 状态 |
|---|--------|--------|------|
| M1 | **完成核心流水线** — 任务从创建到完成可走通全流程 | 端到端执行不报错，输出符合预期 | ✅ done |
| M2 | **消除项目耦合** — anchor 验证和构建命令不硬编码特定项目 | 在非 Swift 项目上执行 sprint 不需要改源码 | ✅ done |
| M3 | **建立质量基线** — 核心脚本有自动化回归测试 | CI 跑通，关键路径有断言保护 | ✅ done |
| M4 | **支持项目级配置** — 声明式定义构建/测试/lint 命令 | 接入新项目只需写配置文件 | ✅ done |
| M5 | **文档任务精简** — 文档类任务自动跳过低价值阶段 | 文档任务流水线减少 plan + quality | ✅ done |

## 4. 当前版本

### 包含

| 能力 | 解决什么问题 |
|------|-------------|
| **任务执行流水线** | agent 自由发挥容易跑偏 → 分阶段执行，每阶段有明确目标和产出 |
| **复杂度自动裁剪** | 简单任务走完整流程浪费时间 → 根据任务复杂度自动跳过不必要的阶段 |
| **方向锚点验证** | agent 执行过程中偏离目标难以发现 → 在关键节点自动校验是否偏离 |
| **长任务编排** | 大任务超出单次 agent 上下文 → 拆分为多个子 sprint 顺序执行 |
| **快速任务入口** | 小任务不需要完整流程 → 提供轻量路径直接执行 |

### 排除

- 多仓库跨项目编排
- 执行数据分析和趋势报告
- 团队协作和权限管理
- GUI / Web 界面

### 主线指标

| 指标 | 衡量方式 |
|------|---------|
| **任务完成率** | sprint 正常结束 vs 中途放弃的比例 |
| **跨项目适用性** | 在非 sprint 自身的项目上能否正常使用 |
| **流水线精简率** | 文档类任务实际跳过的阶段数 |
